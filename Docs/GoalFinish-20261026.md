# RuinRunner 마감 — 2026-10-26

## 실제 수정

- 산탄·관통·대포의 같은 공격에 속한 접촉들이 방금 설치한 표식을 즉시 소모하던 문제를 고쳤다. 다음 직접 공격만 한 번 회수하며, 늦게 도착한 이전 탄환이나 교체한 무기 사본이 표식을 되살리거나 소모하지 않는다.
- 균열 연결은 설치 당시 양 끝점을 사용한다. 플레이어가 움직였다고 피해 구간이 표시 밖의 대각선으로 바뀌지 않는다.
- 가방의 장비 그림과 실제 지정 키 표시를 키웠다. 상점은 그림·이름·요약·가격을 구분하고, 교환은 결과와 두 재료의 그림/효과/필요 수량을 함께 보여 준다. 상세 스크롤과 비용·소모 안내는 유지했다.
- 각성 배지 `✦`를 갈무리에 포함된 `★`로 바꿨다. 누락된 문자 때문에 처음 가방을 그릴 때 발생하던 대체 폰트 처리 지연을 대상으로 한 수정이다. 폰트 검사는 `HasCharacter` 대신 실제 번들 font face의 글리프를 확인한다.
- README의 오래된 무기·장신구 개수만 정리했다. 아이템·적 체력·성장 비용·드롭·시드·생성기·오디오·입력·성능 집계 기준은 이 수정에서 바꾸지 않았다.

## 긴 프레임의 원인 추적

원래 10월 25일 최대 1,341.77ms 표본을 보존했다. 이번 중간 Release `GoalCandidate-20261026-001708`의 정상 원정에서도 동일 시드 `2026100903`, 2지역 지도/가방 경계에서 전환 집계 1,362.62ms, FrameTiming 1,371.73ms가 재현됐다. `Logs/Validation/2026-10-26-goal/package-ranged-final`이 수정 전 자료다.

Editor의 같은 지역·지도·가방 구간에서는 약 68~72ms만 관측됐다. 자동 입력을 끈 실제 지도/가방 입력과 일시정지된 생성 뒤 복귀도 별도로 확인했다. 이 결과만으로 Release 문제가 해결됐다고 판단하지 않았다.

별도 Development Player를 같은 시드·정상 규칙으로 220초만 실행하고 WindowsPlayer 프로파일러를 연결했다. 각성 후 첫 가방의 긴 프레임 468.02ms 중 `PrototypeHud.OnGUI` 462.88ms, `GUIStyle.GetMeshInfo` 456.25ms, `TextGenerator.Prepare` 454.60ms였다. 이 프레임(20512)은 Deep Profiling을 켜기 전이다. 이후 잠깐 켠 Deep Profiling의 비용과 최대 665.00ms 표본도 삭제하지 않았다. 진단 빌드의 수치를 Release 성능 수치와 직접 등치하지 않는다.

갈무리 3종의 실제 face에서 `✦`는 글리프 0/없음, `★`와 `◆`는 존재했다. 반면 `Font.HasCharacter`는 옛 별표도 모두 true였다. Unity 6000.6의 [TextGeneratorPrepare](https://github.com/Unity-Technologies/UnityCsReference/blob/6000.6.0f1/Modules/TextCoreTextEngine/Managed/TextGenerator/TextGeneratorPrepare.cs)에는 누락 글자를 OS 대체 폰트에서 찾는 경로가 있다. 프로파일, 글리프 부재, 최초 각성 배지의 표시 시점을 함께 근거로 최소 수정했다. 확인되지 않은 오디오 종료나 지형 생성 가설 때문에 해당 시스템을 바꾸지 않았다.
