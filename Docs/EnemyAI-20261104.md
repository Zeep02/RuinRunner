# 적 AI 구조 (2026-11-04)

일반 몹은 디렉터 + 유틸리티 AI 구조로 움직인다. 보스 3종은 패턴 전용 AI를 유지한다.

## 네 개의 층

| 층 | 역할 | 코드 |
|---|---|---|
| 블랙보드 | 플레이어 관찰: 체력, 속도, 대시 경과, 피격 경과, 거리 유지 | `EnemyAiDirector.ObservePlayer` |
| 페이싱 | 긴장도로 강도 조절: Build, Peak, Relax | `EnemyAiDirector.UpdatePacing` |
| 분대 | 역할별 자리 배정, 공격권 제한 | `AssignSlots`, `SlotFor`, `TryTakeToken` |
| 개체 유틸리티 | 패턴마다 점수를 매겨 하나를 고름 | `EnemyController.Brain.cs`의 `ChooseMove`, `Score` |

한 마리의 두뇌는 "지금 공격해도 되는가"를 묻기만 하고, 허용 여부는 디렉터가 정한다. 그래서 적이 많아도 한꺼번에 덤비지 않고 앞줄, 뒷줄, 측면으로 나뉜다.

## 유틸리티 점수

```
점수 = 가중치
     + 1 - |거리 - 이상거리| / 사거리폭     거리 적합도
     + 0.8 × (마지막 사용 후 시간 / 6초)     오래 안 쓴 패턴 우대
     - 0.8 (직전과 같은 패턴이면)
     + 플레이어 행동 보정
     + 0.2 (Peak이고 후퇴가 아니면)
```

| 태그 | 조건 | 보정 |
|---|---|---|
| Zone(장판) | 방금 대시함 / 멈춰 있음 | +0.6 / +0.4 |
| Aimed(조준) | 멈춰 있음 / 방금 대시함 | +0.5 / -0.4 |
| Melee(근접) | 플레이어 체력 40% 미만 | +0.5 |
| Gapcloser(돌진) | 거리를 벌림 | +0.8 |
| Retreat(후퇴) | Relax | +0.4 |

1, 2위 차이가 0.35 미만이면 40% 확률로 2위를 골라, 같은 상황에서 늘 같은 행동을 하지 않게 한다. 조준 공격은 플레이어 이동 방향을 0.25초 앞서 겨냥하되 경고선은 그대로라 옆으로 피할 수 있다.

## 페이싱

| 단계 | 진입 조건 | 근접·원거리 공격권 | 쿨타임 |
|---|---|---|---|
| Build | 기본 | 2 / 2 | ×1 |
| Peak | 7초 이상 안 맞았고 체력 50% 이상 | 3 / 3 | ×0.82 |
| Relax | 긴장도 0.65 이상 (0.3 이하로 내려가고 3초 지나면 해제) | 1 / 1 | ×1.2 |

긴장도는 잃은 체력 비율 × 2.2만큼 오르고 초당 0.06씩 내려간다. 적의 공격력과 이동 속도는 바꾸지 않고 압박의 빈도만 조절한다.

## 분대 역할

Frontline(정면), Skirmisher(옆), Flanker(무기가 향하지 않는 등 뒤), Backline(뒤), Support(뒤쪽 좁게), Rusher(자리 없이 돌진), Anchor(고정). 자리가 벽 안이면 플레이어 쪽으로 당긴다. 파도 구성도 역할 기준이라(`RunContent.Squads`) 한 파도에 앞줄과 뒷줄이 함께 나온다.

## 몹 구성

| 스테이지 | 기존 | 추가 |
|---|---|---|
| 외곽 유적 | Grunt, Shooter, Charger, Leaper, Sporeling, RuneTotem | BoneShield, VineLasher, RuinRat, MossArcher, PowderBeetle |

| 봉인의 심부 | SealKnight, Sentinel, Hexer 등 | InkShade, SealGolem, GildedBolter, ChainWarden, SealPriest |

행동은 `EnemyController.StageMobs.cs`에 있다.

## 발표 시연

```bash
Builds/Windows/RuinRunnerPrototype.exe --ai-debug
```

F10으로 켜고 끈다. 왼쪽 아래에 강도, 긴장도 그래프, 공격권 사용량, 플레이어 판단 입력이 나오고, 적 머리 위에 역할과 각 패턴의 점수가 나온다.

```bash
Builds/Windows/RuinRunnerPrototype.exe --ai-log ai.csv
```

결정마다 시각, 적, 역할, 선택, 점수, 후보 점수, 강도, 긴장도, 체력, 공격권을 한 줄로 남긴다.

```bash
Builds/Windows/RuinRunnerPrototype.exe --ai-baseline --ai-log baseline.csv
```

디렉터를 끈 비교 기준이다. 자리, 공격권, 페이싱, 행동 보정 없이 거리와 반복 방지만으로 고른다. 같은 시드로 두 로그를 비교할 수 있다.

## 측정 결과 (2026-11-05, 봇 원거리 빌드, 같은 시드, 약 190초)

| | 지휘 켬 | 지휘 끔(`--ai-baseline`) |
|---|---|---|
| 패턴 결정 수 | 47 | 53 |
| 페이싱 전환 | 8회 | 0회 |
| Peak에서 내린 결정 | 32 | 0 |
| Build에서 내린 결정 | 15 | 53 |
| 결정 순간 평균 공격권 사용 | 1.47 (최대 3) | 사용 안 함 |

이 시험에서는 공격권이 모자라 기다린 적이 없고(`wait-token` 0건) Relax도 나오지 않았다. 지휘를 끄면 공격권 자체를 쓰지 않는다. 공격권 제한과 Relax의 효과를 보이려면 적이 많은 방에서 오래 맞으면서 사람이 직접 플레이한 로그를 쓴다. 표본이 한 판씩이라 난이도 차이의 근거로는 쓰지 않는다.
