# 일반 장검: 3타와 받아내기 반격

일반 장검의 마지막 찌르기를 넓은 마무리 베기로 교체하고, 우클릭 유지 방어를 한 번 받아낸 뒤 자동으로 반격하는 행동으로 바꿨다. 이 문서는 일반 장검의 첫 개선 범위다. 다른 무기군의 전면 재설계나 에픽·전설 개별 행동까지 완료했다는 의미는 아니다.

## 입력과 움직임

- 좌클릭 유지: 정방향 베기 → 역방향 연결 베기 → 넓은 정방향 마무리를 반복한다. 짧은 클릭은 입력 버퍼 동안 다음 공격을 예약하고, 시간이 지나면 사라진다.
- 각 베기는 시작할 때 조준을 고정한다. 공격 중 WASD 이동은 계속 가능하다.
- 우클릭 누름: 비용을 한 번 지불하고 짧은 받아내기에 들어간다. 정면 공격을 실제로 받아냈으면 반격이 강해진다. 받지 못해도 시간이 끝나면 한 번 베기를 내보낸다.
- 우클릭 유지로 방어 시간을 늘리거나 특수행동을 자동 반복할 수 없다. 뒤에서 받은 공격은 막지 못한다.
- 받아내는 동안의 조준과 뒤이어 시작하는 반격의 조준은 각각 해당 행동 진입 시 고정한다.
- 기본 공격의 판정이 이미 발생한 회복 구간에는 짧게 예약한 우클릭으로 받아내기를 연결할 수 있다. 같은 프레임의 좌·우클릭은 우클릭이 우선한다.

비용·재사용 시간·받아내기 시간·버퍼의 공통 기준은 [LongswordActionRules.cs](../Assets/RuinRunner/Runtime/Player/LongswordActionRules.cs)다. 일반 콤보 수치와 범위는 [MeleeComboDefinition.cs](../Assets/RuinRunner/Runtime/Data/MeleeComboDefinition.cs)의 `longsword` 프로필에서 관리한다. `sun_oath`의 별도 기본 콤보는 이번 교체에 포함하지 않았다. 현재 우클릭은 장검군 공통 동작이며, 무기 ID별 고유 행동은 후속 범위다.

## 자세, 판정, 피드백

기존 `External/SscaryMaleCombat/ArmedGripV3`의 정방향·역방향 베기, 가드·가드 복귀 자세와 실제 손 소켓을 사용한다. 원본 몸체 이미지, 캔버스, 손잡이 좌표를 새로 만들거나 바꾸지 않았다. 이동 중에도 기존 보행 변형을 사용한다.

반격의 강한 타격 표현은 별도 상태로 관리한다. 몸체는 일반 베기 손목을 사용하는데 무기만 무거운 공격의 큰 회전각으로 움직이던 불일치를 제거했다. 검광은 기존 손에 연결된 궤적과 같은 판정 시계를 따른다. 받아내기 성공 시 즉시 주변 적에게 보이지 않는 피해를 주지 않고, 이어지는 실제 베기 접촉 때 피해가 발생한다.

연속 화면 검토에서 장검 `Arc/00`의 원형 중심이 다음 프레임보다 원본 캔버스 위쪽에 있어, 검광이 손 뒤에서 앞으로 건너뛰는 결함을 확인했다. 같은 방향의 U자 형태를 유지하고 첫 프레임만 원본 좌표 아래로 13픽셀에 해당하는 렌더 위치를 옮겼다. 다른 프레임·무기군의 위치, 검광 크기, 피해 시계, 원본 PNG·메타는 바꾸지 않았다. 사용자 요청에 따라 `MeleeSlashEffect`의 검광은 몸체와 무기 중 높은 정렬값보다 한 단계 위에 놓아 무기가 검광을 덮지 않게 했다. 이 후속 변경은 컴파일과 원본 파일 해시 보존을 확인했으며, 실제 화면 재검토는 별도 기록한다.

마무리·반격은 실제 적중한 경우에만 `CameraFollow.MeleeFinisherImpact()`를 호출한다. 한 공격의 여러 대상이나 여러 접촉이 이를 중복 호출하지 않는다. 카메라 쪽 별도 제한과 게임 컨트롤러의 짧은 히트스톱이 연결되며, 헛스윙에는 명중 히트스톱을 주지 않는다.

## 취소와 자원

대시, 장비 교체, 순간이동, 사망, 스테이지 전환 안전 상태, 일시정지는 남아 있는 근접 판정을 없앤다. 지불한 마나와 남은 공격·특수행동 회복 시간은 보존한다. 일시정지는 입력 버퍼도 지우며, 재개 후 기존 좌·우클릭을 놓고 새로 입력해야 전투가 다시 시작된다. 지연 단검·권총 동작도 취소 세대와 중단 상태를 확인한다.

마나 자연 회복은 취소 이후에도 정상 진행한다. 따라서 일정 시간 뒤의 마나가 지불 직후보다 늘었다는 사실만으로 환급으로 판단하지 않는다. 회귀 검사는 실제 프레임의 `Time.deltaTime` 누적과 재생량을 계산해 추가 환급 여부를 분리한다.

## 확인한 결과와 한계

[LongswordActionRegression20261004.cs](../Tools/Validation/LongswordActionRegression20261004.cs)는 공급한 플레이어·고정 적을 사용하고, 좌·우클릭·이동·대시는 실제 `GameAction` 경로로 입력한다. 정면·후면 피격은 분리된 검사용 자극이다. 정상 원정 완주 검증은 아니다.

최종 실행 [120858 결과](../Logs/Validation/2026-10-04-sword-action/120858/result.txt)는 33개 검사를 통과했다. 3타의 실제 판정, 이동·조준, 짧은 입력 버퍼, 유한한 받아내기, 정면 성공과 후면 취약성, 실제 반격, 명중에만 발생하는 피드백, 각 취소 경계, 마나 부족을 확인했다. 히트스톱 관련 실측은 명중 때 피드백 콜백이 한 번 호출되고 헛스윙에는 호출되지 않는 것까지다. 실제 게임의 시간 배율 변화나 청취 결과까지 검증한 것으로 세지 않는다.

대시 취소의 실측은 비용 10, 지연 판정 0이었다. 실제 델타 합 0.683193초에 대한 예상 마나 73.415970과 실측 73.415950의 차이는 -0.000015로, 취소 환급이 없었다. 최초 [120555 실패](../Logs/Validation/2026-10-04-sword-action/120555/result.txt)는 자연 회복을 무시한 검증식 때문이었다. 실패 기록은 보존했고, 조건을 비용·지연 판정·자연 회복을 뺀 환급으로 나눠 다시 검사했다.

[LongswordMotionReview20261004.cs](../Tools/Validation/LongswordMotionReview20261004.cs)는 8방향 × 정지·이동의 실제 화면 프레임을 기록한다. 임시 장면의 공급된 캐릭터와 정면 피격 자극을 사용하며, 원본 화면의 고정 영역을 보간 없이 자른다. 실제 벽시계 시간, 시뮬레이션 시간, 프레임 번호, 캡처 간격, 자세와 손잡이 오차를 저장하고, `review.html`은 원래 시간 간격 그대로 1배속 재생한다. 요청 프레임 속도가 실제 캡처 프레임 속도를 증명하지 않는다.

첫 설정 실행 `120915`는 GameViewSizes의 상속된 static 속성 조회 오류로 실패했다. 도구의 reflection 범위를 수정한 `121059`는 16클립·1,379프레임의 입력 구성과 손잡이 오차 0 검사를 통과했다. 다만 PNG 저장 지연이 뒤 15클립 첫 대기 프레임의 시뮬레이션 델타에 들어가, 첫 클립과 이후 클립의 우클릭 예약 시점이 달라졌다. 베기 프레임은 진행도 0부터 실제 시간대로 기록됐지만, 동일한 입력 구성의 최종 근거로 채택하지 않는다. 기존 자료와 비활성 오디오 풀 경고도 보존했다.

도구는 저장 뒤 두 개의 정상 프레임을 소비한 다음 클립의 시계를 시작하도록 보완했다. 소비한 시간은 `warmup.csv`에 별도 보존한다. 또한 검사용 별도 설정 객체로 전투 오디오 출력을 막고 종료 시 원래 설정 객체를 복구한다. 사용자 설정 파일을 수정하지 않는다. 해당 모션은 임시 장면, 실제 `GameAction` 입력, 공급한 정면 피격 자극을 사용하며 적 AI와의 전투, 실제 타격 대상, 소리, 실제 게임 히트스톱 또는 전체 캠페인을 검증하지 않는다. 최종 8방향 시각 품질은 새 캡처를 보고 별도로 판정한다.

보완 후 [121558 결과](../Logs/Validation/2026-10-04-sword-motion/121558/result.txt)는 16클립·1,664프레임을 기록하고 손잡이 오차 0, 각 클립의 3타와 반격 판정, 원래 월드·입력·화면·시간·AutoTick 복구 검사를 통과했다. 각 클립은 104프레임, 실제 1.7146~1.7211초이며 관찰된 캡처 빈도는 59.84~60.07Hz였다. 최대 캡처 간격은 0.024416초다. 이는 해당 짧은 에디터 기록의 관측값이며, 게임 전체의 60fps 성능 보장은 아니다.

[독립 시간 분석](../ArtDirection/Review-20261004/sword-action/timing-121558.json)은 64번의 공격 모두 진행도 0에서 시작하고, 공격 중 최대 시뮬레이션 델타가 0.021127초였음을 확인했다. 저장 때문에 생긴 15개의 큰 델타는 `warmup.csv`에만 있고 녹화 클립에는 없다. [review.html](../Logs/Validation/2026-10-04-sword-motion/121558/review.html)은 로컬 HTTP 서버에서 열면 실제 캡처 시각대로 재생한다. 파일로 직접 열어 `fetch`가 차단되면 기존 검토 서버를 사용한다.
